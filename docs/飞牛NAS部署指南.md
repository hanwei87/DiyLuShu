# 飞牛NAS 部署指南（外网访问）

目标：把路书应用放到飞牛NAS（fnOS）上运行，通过内网穿透从外网电脑访问使用。

## 〇、先懂一个关键原理（重要）

**NAS只负责"发网页"，不保存任何人的数据。** 这套应用是无后端的纯前端程序：

- 每台电脑/手机打开它时，数据都存在**那台设备自己的浏览器**里（"授权文件夹"写的也是**当前这台电脑**的磁盘，不是NAS）；
- 所以：公司电脑做的路书，回家电脑上是看不到的——跨设备靠「我的→导出全部数据 / 导入备份」搬运；
- 多设备共用一份数据（真正意义上的"登录后大家看同一份"）需要第二版的 C/S + 数据库架构，你已规划的 NAS 内网穿透是它的第一步。

## 一、生成部署包（在Mac上做）

双击项目里的 **「打包部署.command」**，会生成 `deploy-dist/` 文件夹——只含网页本体，**自动排除你的个人数据**（路书数据*文件夹）、文档、测试等。

以后更新应用：改完 → 重新双击打包 → 用新 `deploy-dist` 覆盖NAS上的旧文件 → 浏览器 Ctrl+F5。

## 二、上传到飞牛

任选其一：
- **文件管理器**：fnOS 网页 → 文件管理 → 把 `deploy-dist` 里的内容上传到某个文件夹（建议路径简短无空格，如 `/vol1/1000/lushu`）；
- SMB 共享直接拖拽；
- SCP：`scp -r deploy-dist/* user@NAS_IP:/vol1/1000/lushu/`。

## 三、在飞牛上跑起来（Docker，推荐）

fnOS 应用中心自带 Docker，纯界面操作即可，**不需要命令行**：

1. fnOS → **Docker** → 镜像仓库 → 搜索 `nginx` → 下载 `nginx:alpine`；
2. **本地镜像** → 找到 nginx:alpine → **创建容器**：
   - 名称随意（如 lushu）；**勾选"开机自启/自动重启"**（restart: always）；
   - **端口映射**：本地端口 `8124` → 容器端口 `80`；
   - **挂载路径（存储空间）**：把 `/vol1/1000/lushu`（你上传文件的文件夹）映射到容器的 `/usr/share/nginx/html`，权限选**只读**；
3. 启动容器。

会SSH的话也可以用项目里现成的 [deploy/docker-compose.yml](../deploy/docker-compose.yml)（改好路径后 `docker compose up -d`）。

## 四、内网验证

浏览器打开 `http://NAS的内网IP:8124/`（如 `http://192.168.1.10:8124`），能看到应用即成功。此时先在自家Wi-Fi下的手机/电脑试一遍。

## 五、内网穿透选型（外网访问）

| 方案 | 适合 | 说明 |
|---|---|---|
| **飞牛 fn Connect**（先查） | 已在用fn Connect | 新版fnOS的远程访问若支持自定义应用/端口，直接把 8124 加进去最省事；不支持再用下面的 |
| **frp + 云服务器** | 有VPS、追求长期稳定免费 | 自己完全可控；示例配置见下 |
| **cpolar / 花生壳 / natapp** | 不想折腾、可接受付费 | 注册即得 HTTPS 域名，5分钟搞定；免费版带宽小（约1Mbps）、域名随机，稳定使用建议付费档 |
| **Tailscale / ZeroTier** | 只有**自己的**设备用 | 组私有网络，不暴露公网、最安全免费；缺点是每台设备都要装客户端，且默认HTTP |

frp 客户端示例（`frpc.toml`，跑在NAS上）：

```toml
serverAddr = "你的云服务器公网IP"
serverPort = 7000
auth.token = "你的密码"

[[proxies]]
name = "lushu"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8124
remotePort = 8124
```

访问 `http://云服务器IP:8124`。注意：这是**HTTP**，见下一节的限制；要HTTPS需自备域名+证书（frps 配 vhostHTTPS），或直接用商业隧道的 HTTPS 域名更省事。

## 六、必须用 HTTPS 的两个功能（选穿透方案的决定因素）

浏览器规定以下功能**只在 localhost 或 HTTPS 下可用**，普通HTTP远程地址会失效：

- **授权文件夹自动保存**（File System Access API）→ 降级为：数据存浏览器内存储+「我的→导出/导入备份」手动搬运（应用顶部会自动出现黄色提示条）；
- **定位到当前位置**（Geolocation）→ 地图显示默认中心，其他功能不受影响。

所以：**想在外网电脑获得完整功能，优先选自带 HTTPS 的方案**（cpolar/花生壳的 https 域名，或 frp+域名+证书）。只是自己临时用、能接受手动导出备份的话，HTTP 也够。

## 七、高德后台设置（建议）

lbs.amap.com → 控制台 → 你的Key → **安全域名**：把穿透得到的公网域名加进白名单（防止别人拿到你的Key盗用配额）。天气Key是服务端风格调用，同样建议妥善保管，不要发给别人。

## 八、安全须知

- 应用本身**没有登录功能**：任何拿到公网地址的人都能打开这个网页（看到的是空数据，但会消耗你的高德配额）；
- 建议：① 地址保密；② 用支持**访问密码**的隧道（cpolar/花生壳均有 basic auth 选项）；③ 容器挂载已是只读，NAS 上不会被网页改文件；
- 公网部署后如发现异常用量，先去高德控制台换Key。

## 九、常见问题

- **打开是 403/404**：挂载路径错了——容器里 `/usr/share/nginx/html` 下必须直接是 `index.html`（不是套了一层文件夹）；
- **改了文件没生效**：浏览器缓存，Ctrl+F5 强制刷新；或容器重建一次；
- **外网能打开但地图空白**：检查高德Key的安全域名是否包含当前访问域名；
- **顶部黄色"HTTP限制"提示**：正常现象，见第六节，换HTTPS地址即消失。
