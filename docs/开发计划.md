# 开发计划 · 本地路书 Web 应用 v1

> 依据 [PRD.md](../PRD.md)（v1.0 已确认）与 [页面结构与交互设计.md](页面结构与交互设计.md) 制定。
> 目标：按里程碑顺序执行，每个里程碑结束时都有"可运行、可自测"的版本。

---

## 1. 技术选型（已定，不再纠结）

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **原生 ES Modules + JSDoc 注释，无构建步骤** | 改完刷新即生效，无工具链负担；本地应用规模不需要框架 |
| 拖拽 | **SortableJS**（vendor 本地单文件） | 跨列表拖拽、吸附指示线开箱即用，自写 HTML5 DnD 成本高且坑多 |
| 浏览器存储镜像 | **idb-keyval**（vendor 本地单文件） | 50行封装 IndexedDB，做镜像兜底 |
| 地图 | 高德 JS API 2.0（CDN 加载，需联网） | 官方能力：AutoComplete / PlaceSearch / Driving |
| 样式 | 手写 CSS（变量主题，单文件 app.css） | 无依赖；桌面端 min-width 1200px |
| 本地服务 | `server.py`（约20行，纯静态 + 禁缓存头）+ 双击启动脚本 | File System Access API 需 http(s) 环境，file:// 不可靠；禁缓存头避免开发时改了不生效 |
| 单元测试框架 | 不引入 | v1 以 PRD 验收清单人工+浏览器自动化自测 |

**第三方仅 2 个本地 vendored 文件**（vendor/ 目录），除高德 CDN 外应用完全离线可用（地图功能除外）。

## 5. 关键技术方案（实现约定）

**① 文件夹授权与权限续期**
首启引导 → `showDirectoryPicker` → 句柄存 IndexedDB。之后每次启动 `queryPermission`：`granted` 直接用；`prompt` → 顶横幅一次点击续期（Chrome 122+ 可在授权弹窗选"每次访问时允许"，基本不再问）。未授权期间一切可浏览（读 IndexedDB 镜像），改动暂存内存，授权后全量 flush。

**② 原子写**：File System Access 的 `createWritable()` 本身写临时文件、close 时原子替换——统一只经 `writeJSON()` 写盘，禁止其他直写路径。

**③ 防重复入库**：以 `amapPoiId` 为主键判重；无 poiId 的候选（少数）以 `名称+经纬度(1e-4)` 兜底判重。

**④ 画线策略与配额**：Driving 请求按"相邻两点一段"发起并缓存（key=两点id+顺序），只在顺序变化时重查该天受影响段；个人Key免费额度足够。直线距离优化不产生任何请求。

**⑤ 行程条目 = 引用**：`stopItemIds` 只存信息库条目 id；渲染时实时查信息库取名。信息库条目改名 → 所有路书即时同步（PRD §4.3）。

## 6. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| File System Access 权限每次重启要确认 | 体验打断 | 引导选"每次访问时允许"；镜像兜底保证不打断编辑；横幅一键续期 |
| file:// 直接双击打开 HTML | 地图/授权不可用 | 只经启动脚本访问 localhost；页内检测 file:// 给出提示 |
| 高德配额/网络异常 | 搜索、画线失败 | 防抖+段缓存降请求；失败 toast + 重试按钮 |
| 拖拽与滚动/触控板冲突 | 体验问题 | SortableJS 已处理；仅桌面 Chromium 为目标 |
| 用户误删数据 | 丢行程 | 删除全部二次确认+影响说明；导出备份入口常驻⚙；JSON 文件可手工拷贝 |
